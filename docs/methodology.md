# Development Methodology

The course adopts a specification-driven and AI-assisted software
development workflow adapted for an educational environment.

The development cycle is:

**SPEC → BUILD → VALIDATE → EXPLAIN → COMMIT**

## SPEC

Before implementation, students must clearly describe what should be
developed.

A specification may contain:

- context;
- task description;
- functional requirements;
- constraints;
- acceptance criteria;
- validation procedures;
- out-of-scope items.

## BUILD

Students implement the solution using appropriate development tools,
including:

- Kotlin;
- Android Studio;
- Jetpack Compose;
- technical documentation;
- Git and GitHub;
- AI-assisted development tools.

## VALIDATE

The implementation must be checked against the acceptance criteria
defined in the specification.

A feature is not considered complete only because the code compiles.

Students must demonstrate that the expected behavior is actually
achieved.

## EXPLAIN

Students must be able to explain:

- what was implemented;
- how the implementation works;
- which technical decisions were made;
- how AI tools were used;
- what was changed after AI-generated suggestions;
- how the solution was validated.

## COMMIT

Completed increments must be versioned using Git and submitted through
GitHub.

Each Sprint should produce a traceable development history through
commits and Pull Requests.

## Human-in-the-Loop

AI-generated output must always be reviewed by a human.

AI tools may assist with implementation, debugging, documentation,
testing, and exploration, but they do not replace student responsibility
for the final software artifact.
