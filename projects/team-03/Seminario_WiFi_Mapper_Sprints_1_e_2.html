Sprint 2 · SPEC-002 · A Ideia

A Evolução: De Estático para Reativo
O LIMITADOR DA SPRINT 1
A Primeira Tela era Apenas Estática
O usuário via a identidade do produto e o botão, mas ao tocar na tela nada acontecia. Para que o produto faça sentido prático, ele precisa diagnosticar a qualidade do sinal e dar retorno visual imediato.
A INTERAÇÃO ESCOLHIDA (SPRINT 2)
Verificação Reativa de Sinal Wi-Fi
Ao tocar no botão "Iniciar Verificação", o aplicativo simula uma medição ativa de intensidade de sinal e redesenha a tela na hora com feedback visual rico:
  • Valor numérico medido em dBm (ex: -45 dBm, -68 dBm, -85 dBm);
  • Setor colorido aceso no Radar em Canvas (Verde, Laranja ou Vermelho);
  • Chip qualitativo com texto e cor correspondentes.
Fluxo: Estado Inicial (Aguardando) → Toque (onClick) → Mutação do Estado → Recomposição da UI

Sprint 2 · SPEC-002 · Estado
WI-FI MAPPER · TEAM 03
Modelagem do Estado: SignalStatus
// Enumeração que encapsula os dados e os atributos visuais de cada estado enum class SignalStatus( val label: String, // Texto exibido no chip de status val dbm: Int?, // Valor em dBm (ou null quando em espera) val sectorColor: Color, // Cor da iluminação no Radar Canvas val textColor: Color // Cor temática do texto e do ícone ) { NONE( label = "Aguardando", dbm = null, sectorColor = Color.Transparent, textColor = Color(0xFF8FA3B8) ), STRONG( label = "Sinal Forte", dbm = -45, sectorColor = Color(0xFF4CAF50), textColor = Color(0xFF81C784) ), MEDIUM( label = "Sinal Médio", dbm = -68, sectorColor = Color(0xFFFF9800), textColor = Color(0xFFFFB74D) ), WEAK( label = "Sinal Fraco", dbm = -85, sectorColor = Color(0xFFE53935), textColor = Color(0xFFFF5252) ) }
A VARIÁVEL REATIVA
var signalStatus by remember { mutableStateOf(SignalStatus.NONE) }
remember: retém o valor na memória durante as recomposições.
mutableStateOf: notifica o Compose para redesenhar a tela quando mudar.
by: sintaxe limpa de delegação de propriedade do Kotlin.
O EVENTO ONCLICK
Button(onClick = { val statuses = listOf(STRONG, MEDIUM, WEAK) signalStatus = statuses.random() // Dispara recomposição! })
Sorteia um novo status e atualiza a variável. A tela inteira se recompõe automaticamente sem chamadas manuais.

WI-FI MAPPER · TEAM 03
Desenho Vetorial do Radar (Canvas)
@Composable fun RadarView(status: SignalStatus, modifier: Modifier = Modifier) { Box(modifier = modifier, contentAlignment = Alignment.Center) { Canvas(modifier = Modifier.fillMaxSize()) { // 1. Setor circular iluminado na cor do status if (status != SignalStatus.NONE) { drawArc( color = status.sectorColor.copy(alpha = 0.35f), startAngle = -90f, sweepAngle = 60f, useCenter = true ) } // 2. Círculos concêntricos da grade drawCircle(color = gridColor, radius = maxRadius, style = Stroke(strokeWidth)) drawCircle(color = gridColor, radius = maxRadius * 0.68f, style = Stroke(strokeWidth)) drawCircle(color = gridColor, radius = maxRadius * 0.36f, style = Stroke(strokeWidth)) // 3. Retas de mira ortogonais (X e Y) drawLine(color = gridColor, start = Offset(0f, centerY), end = Offset(w, centerY)) drawLine(color = gridColor, start = Offset(centerX, 0f), end = Offset(centerX, h)) } // 4. Textos centrais: Ícone + dBm + "DBM" } }
VANTAGENS DO CANVAS NATIVO
• Desempenho: renderização matemática acelerada por GPU sem carregar imagens rasterizadas pesadas.
• Resolução Perfeita: escala vetorial que não perde nitidez em nenhuma densidade de tela.
• Reatividade Total: o arco e a cor mudam instantaneamente conforme a variável de estado.
